Goal: add RL (GRPO chosen, not PPO) for the **LingBot-VA** model (model_type `lingbotva`, a Wan-Video diffusion video+action model) in RLinf, on top of PR#1220 (branch `pr-1220`, fetched from `pull/1220/head`) which added its SFT + Libero-Object eval. User (zrzhou1989) will later provide an SFT-trained checkpoint with ~30-50% success rate on Libero-Object and ask to run GRPO on Libero-Object.

Key design decisions (agreed 2026-06-03):
- **GRPO first** (critic-free, `adv_type: grpo`, `loss_type: actor`); PPO+value-head is a later optional extension.
- Now-scope: build checkpoint-independent **scaffolding + unit-tested math** (config, model_type wiring, model RL method skeletons, SDE/Gaussian log-prob math with standalone tests). Substantive runs wait for the checkpoint + the external lingbot-va repo (`${LINGBOT_VA_REPO_PATH}`, cloned from github.com/robbyant/lingbot-va.git).

Core approach: mirror how RLinf already does RL on flow-matching policies (OpenPI pi0/pi05 and the existing `lingbotvla` model). Make ONLY the **action-denoising chain** stochastic (SDE, `noise_method: flow_sde`); keep video-latent diffusion deterministic (treat as world-context). Action log-prob = per-step diagonal-Gaussian transition density. `predict_action_batch` stores latent `chains`+`denoise_inds`+conditioning in `forward_inputs`; `default_forward` re-runs the one stored denoise step with gradients. Template: `rlinf/models/embodiment/lingbotvla/lingbotvla_action_model.py` (sample_actions ↔ get_log_prob_value) and `rlinf/models/embodiment/openpi/openpi_action_model.py`.

Two HARD problems (need real repo/checkpoint):
1. Recompute conditioning: LingBot-VA action transformer is conditioned on the video-latent KV cache (expensive video diffusion), unlike LingbotVLA's cheap VLM prefix. Must store/replay post-video conditioning for `default_forward`, or re-run video diffusion (Nx compute).
2. Stateful rollout: RL uses `MultiStepRolloutWorker` which is STATELESS across chunks (no per-step raw obs / KV-replay) — the same gap that forced the PR's dedicated `eval_lingbotva.py`. LingBot-VA needs KV-cache replay for non-zero SR. Plan: a `LingbotVARolloutWorker(MultiStepRolloutWorker)` keeping per-env `LingbotVAEpisodeState`.

Critical verification gates: (1) recompute consistency — `default_forward` logprob == rollout `prev_logprobs` at same weights (ratio≈1); (2) RL rollout SR ≈ eval SR (~30-50%) before any update; (3) reward/advantage sanity.
